# Phase 1 对抗审查：计划

> 生成者/评审者分离：以下三个视角各自只对照原始意图与 `docs/PLAN.md` 提出问题，最后一节为裁决与修订。

## Quant Domain Critic
1. **前视偏差**：社区代码常见 `shift(-1)`、用当日收盘价当日成交。→ Runner 必须统一把信号 `shift(1)` 后再计收益，策略代码无法绕过；抽取器需静态标记 `shift(-n)`。
2. **成本模型必须是 A 股的**：佣金双边、印花税仅卖出、滑点；不能用一个笼统的 bps。
3. **样本划分必须事先固定**：train/test 由 Runner 固定（70/30 按时间），策略作者无法选择；结果 JSON 必须声明。
4. **稳定性**：只看 OOS 总收益容易被一段行情主导 → 将 OOS 切为两半，两半都需成本后为正。
5. **多重检验**：同一策略反复重跑调参会“刷”出好结果 → 记录 attempt 次数，门禁 Sharpe 阈值随 ln(N) 上调。
6. **合成数据会骗人**：样例数据必须明确标注 synthetic，结论不能对外当真；真实数据走 rstdx。
7. **幸存者偏差**（社区只分享好看的）：P0 至少保留 source / author / 抓取时间，并强制归档失败案例，不只保留通过的。

## Security Critic
1. 沙箱：`NetworkMode=none`、`ReadonlyRootfs`、`CapDrop=ALL`、`no-new-privileges`、`PidsLimit`、内存/CPU 限制、超时后强制 kill+remove；绝不挂 docker.sock；非 root 用户运行。
2. 数据卷只读、策略代码目录只读、结果卷单独可写且按 job 隔离。
3. 行情拉取只能在宿主机（沙箱外）进行，沙箱仍然断网。
4. 审计日志：追加写 + 哈希链 + SQLite 触发器禁止 UPDATE/DELETE；`audit verify` 可检出篡改。
5. 抓取内容是不可信输入：路径穿越（`id` 里带 `../`）、超大文件、LLM 提示注入 → 生成内部 UUID，不用外部 id 当路径；限制大小；LLM 输出只当数据。
6. 进程隔离后端安全性弱于容器，必须在 UI/CLI 上明确标为 dev。

## UX/Product Critic
1. 用户要能看懂“为什么被卡住” → 每个策略显示状态流转与失败/拒绝原因。
2. 一键溯源：策略 → 原始帖子 URL / 归档原文 / 沙箱日志。
3. 晋升必须人工确认，Dashboard 有明确确认动作，并写审计。
4. 支持重跑（Rejected/Failed → 重新回测），并显示 attempt 次数。
5. CLI 输出要可读也要可机器解析（`--json`）。

## 裁决（已纳入实现）
全部采纳；其中「幸存者偏差的来源质量评分」「多源交叉验证」「regime 稳定性」推迟到 P1，仅在 P0 保留字段与 OOS 两半稳定性检查。
