# 06 对抗审查：平今 / 交易所日历 / QIFI / 交易统计（2026-10-21）

每一项都先问"它怎样会骗人或破坏可信边界"，再给出对应的测试或处理。

## A 平今
| 攻击 / 疑点 | 处理 |
|---|---|
| 日线回测里突然出现平今费，结果被改变 | 日线的交易日就是 bar 日期，开仓和平仓永远不在同一交易日。测试 `daily_bars_never_pay_close_today` 每天来回反手 30 次，平今 lot 仍为 0；已有期货测试的数值不变 |
| 夜盘开仓被当成"昨仓" | 用交易日标签而不是日历日期判断：夜盘 bar 带的是下一交易日。测试 `intraday_round_trip_pays_close_today_tier` 的第三种情形覆盖了这一点 |
| 平仓数量超过持仓 | `Ledger::close` 最多只平掉持有的数量（有测试） |
| 先平今还是先平昨，选错了会少算成本 | 按交易所给默认值，并可按品种覆盖；上期所按"较便宜的一档先平"建模，这是对策略有利的一侧，已在文档里标明 |
| 换月当天又在同日平掉新合约 | 换月后的新 lot 记为当日开仓，同日再平就按平今收费 |
| 爆仓后账本还残留 lot | 权益 ≤ 0 时持仓和账本一起清空 |

## B 交易所日历
| 攻击 / 疑点 | 处理 |
|---|---|
| tushare 返回空表或失败，覆盖掉旧快照 | 只要没有开市日就不写文件，并以非零码退出 |
| 快照没覆盖到的日期 | 退回按工作日判断，`source()` 会写明用的是哪种日历 |
| 7x24 仿真前置在节前推夜盘 tick | 只标记（`flagged`），不丢弃也不改变交易日归属 |
| 快照被人篡改 | 抓取时把 sha256 写进审计链，可以与当前文件比对；快照目录在 data/ 里，仍属于同一 uid（与已知缺口相同） |
| 硬编码节假日 | 没有。测试里的国庆样例只是测试数据 |

## C QIFI
| 攻击 / 疑点 | 处理 |
|---|---|
| 导出被当作券商对账单或下单入口 | `orders` 恒为空，`broker_name` 写明"没有券商（仅观察的模拟账户）"，`cmsq.observe_only=true`，不存在任何发送路径 |
| 对没通过 vault 的策略导出漂亮账户 | 只接受已晋升的策略，且必须有 `passed==true` 的 vault 任务；e2e 验证了被拒策略导出会被拒绝 |
| 窗口外的开仓污染 vault 窗口 | `trades` 只列出 vault 窗口内的成交；持仓取最终状态 |
| 代码与许可证 | 只按公开的 QIFI 字段布局自行实现，没有使用 QUANTAXIS 或 qa-rs 的代码 |

## D 交易统计
| 攻击 / 疑点 | 处理 |
|---|---|
| 用胜率、盈亏比去"刷"门禁 | 门禁不读取它，`gate_never_uses_trade_stats` 用源码检查守护；字段名 `display_only` 也会显示在界面上 |
| 窗口前开仓、窗口内平仓，被拆成一笔反向的假交易 | 对全部成交做配对，再按出场位置过滤（测试 `window_keeps_trade_opened_before_it`） |
| 拆股、分红、换月制造假盈亏 | 在复权价尺度上配对，A 股数量也做相应换算；换月腿成本单独列出 |
| 一笔出场对应多个 FIFO 切片，导致笔数虚高 | 同一入场、同一出场、同一方向的切片合并为一笔 |
| 打平的交易算作盈利 | 计为亏损，口径已写在 note 里 |
